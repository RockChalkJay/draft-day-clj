# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A fantasy football auction-draft assistant (auction-focused, VBD). Clojure backend serves a stateless JSON API; a ClojureScript/re-frame SPA renders a live draft board and drives all draft state from the browser.

It has an in-season half too: a Waivers view that syncs a real league's rosters, re-projects every player over the games that are left, and prices a claim against a FAAB budget. Draft-day dollars stop at the draft — see "The in-season half" below.

## Commands

Backend (Leiningen, `project.clj`):
- `lein repl` — nREPL for backend dev
- `lein test` — run all Clojure tests
- `lein test draft-day.rankings.value-test` — run one test namespace
- `lein test :only draft-day.rankings.value-test/value-conserves-to-budget` — run one test
- `lein test :integration` — the live vendor contracts, which `lein test` excludes
- `lein run` — start the http-kit server (`draft-day.server/-main`), reads `PORT` (default 8080)

**Tests reach no third-party service.** `lein test` stays offline by stubbing the fetch
function *nearest the wire* at its own namespace's boundary — the suite's existing
convention (`nflverse/http-get-string`, `league-sync/fetch-raw-rosters`,
`pipeline/load-weekly`). Watch `enrich-universe`, which fans out to more fetchers than is
obvious: `pos-tier-tasks` alone is a dozen FantasyPros scrapes, so a test reaching it has
to stub `fetch-pos-ecr` as well as the seven named fetchers. Nothing enforces this, and
`best-effort` swallows what a fetch throws, so a test that reaches a vendor passes exactly
like one that does not.

Tests that *should* hit a vendor live in `test/draft_day/integration/`, tagged
`^:integration`, and assert against a completed season so they do not fail every August.
They exist for the failure a fixture cannot see — a vendor changing shape — which is the
class behind the injury-badge, `WSH`/`WAS` and `LA`/`LAR` traps described below.

Frontend (shadow-cljs, `:lein true` so it shells to `lein` for the JVM/classpath):
- `npx shadow-cljs watch app` (or `npm run watch`) — dev build with hot reload, served alongside `resources/public` on port 8280
- `npx shadow-cljs release app` (or `npm run release`) — production build
- `npm test` (`shadow-cljs compile test && node out/node-tests.js`) — the `:node-test` build, covering the cljs-only namespaces that `lein test` cannot reach — `events`, `subs`, `waivers` and six under `views/`. `src/cljc` is covered by `lein test` instead, so cljs tests are only worth writing for genuinely browser-side behaviour.

**JAVA_HOME gotcha**: Homebrew's JDK is keg-only and not on PATH. `lein` finds Java fine, but `shadow-cljs` needs it exported first:
```
export JAVA_HOME=/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home
```

Env vars the ingestion pipeline reads: `DRAFTDAY_OFFLINE=1` forces the bundled sample universe (no network calls — useful for tests/dev); `DRAFTDAY_CACHE_TTL_HOURS` controls the disk-cache freshness window (default 24); `DRAFTDAY_WEEKLY_TTL_HOURS` is the same window for the weekly line, which moves far faster (default 1); `DRAFTDAY_TRENDING_TTL_HOURS` is Sleeper's trending adds' (default 1); `DRAFTDAY_AS_OF_WEEK=N` truncates the in-season weekly rows at week N, which is the only way to exercise the waiver half outside the season (the current season's weekly file 404s until week 1 is played, and last season's has nothing left to project).

`lein test :integration` reads four more: `DRAFTDAY_ESPN_SWID`, `DRAFTDAY_ESPN_S2` and `DRAFTDAY_ESPN_LEAGUE` are what `test/draft_day/integration/espn_league_test.clj` needs to check ESPN's stat ids, slot table and team abbreviations against a live league; `DRAFTDAY_ESPN_SEASON` defaults to the current one. Without them the suite skips out loud rather than passing quietly.

Research harnesses (Leiningen `:dev` profile, `dev/` on the source path — active by default for `repl`/`test`/`run`, so no `with-profile` needed):
- `lein run -m draft-day.benchmark.report --help` — score a `rankings.model` against real historical outcomes; see `dev/draft_day/benchmark/report.clj` for flags (`--models`, `--seasons`, `--compare`, `--power-report`, `--simulate`, etc.)
- `lein run -m draft-day.replay.report` — replay a real historical auction draft and compare Worth's picks against what was actually paid
- `lein run -m draft-day.faab.report` — what real Sleeper leagues pay for waiver claims, from a crawled corpus of FAAB auctions (`--crawl` to extend it, `--prior` to print the tables `bid_prior.cljc` holds)

## Architecture

### Split and statelessness

`src/clj` is the backend, `src/cljs` is the frontend SPA; `src/cljs` is also on the backend's classpath (see `project.clj` comment) purely so shadow-cljs can find it via `:lein true`.

The server is intentionally stateless about the draft: its only server-side state is caches of provider data — the shared, in-memory `players` universe (an atom in `api/routes.clj`, backed by a disk cache), the weekly line, and each synced league's bid history (`ingestion/transactions.clj`), all re-fetchable. All draft-in-progress state (teams, picks, bankrolls) lives in the browser's re-frame db and is round-tripped as a `league-state` map on every `POST /api/rankings` call. This means the rankings engine is a pure function of `(players, scoring, roster-config, league-state)` — no session state to reconcile server-side.

### Backend: ingestion -> rankings engine -> API

**Ingestion** (`draft_day/ingestion/`) resolves the player universe with a fallout chain: `offline-sample -> fresh-cache -> live -> stale-cache -> bundled-sample` (`pipeline.clj`). The base universe comes from Sleeper (`sleeper.clj`, free/keyless); FantasyPros (`fantasypros.clj`, scraped via Jsoup for ECR/tier/floor-ceiling inputs) and ESPN (`espn.clj`, live auction values, fetched via raw `java.net.http` because http-kit's client chokes on the ~37MB response) are best-effort enrichments left-joined onto it by `(name, position)` key (`merge.clj`, `match.cljc`).

Every enrichment fetch goes out at once: `pipeline/enrichment-tasks` names them all as best-effort thunks keyed by their `:sources` label and `parallel.clj` runs them concurrently (cancelling the stragglers if the deref escapes), while the *joins* stay sequential and in `scoring/formats` order so the `:sources` report reads the same every run. Per-vendor politeness lives with the vendor, not with `parallel.clj` — `fantasypros/fetch-page` holds that host to `max-in-flight` connections, because twenty-odd simultaneous scrapes from one IP earn a 429, and a 429 here is not an exception but a silently empty column cached for a day. Sleeper's limit is `ingestion/sleeper_http.clj`, the one door every request to that host goes through, so the universe, the realized weeks, import, sync and bid history share one limit per server rather than one each.

Columns that vendors publish *per scoring format* — FantasyPros ECR and auction values, Sleeper ADP — are fetched for all three formats and stored side by side under `:vendor/by-format`; the format is required on every FantasyPros fetch and an unknown one throws (`fantasypros/cheatsheet-url`), because falling back to PPR is silent in the worst way — the join succeeds and reports a full row count while a standard league reads PPR prices. `rankings/vendor.clj` flattens the matching one onto the flat keys at request time (`scoring/format-of` maps a custom config to its nearest published format by reception weight). The universe cache is shared across leagues, so the choice cannot be made at ingestion — baking in PPR is what made a standard league read PPR tiers, rank spread, market prices and ADP. ESPN is deliberately *not* format-scoped: it publishes the same auction value under both its PPR and STANDARD rank types. Cache is Transit on disk, versioned by `pipeline/schema-version` so an old file is never found rather than deserializing cleanly into missing columns — currently `data/players_cache.v10.transit`, with the in-season weekly line cached separately as `data/weekly_projections.v3.transit`. The bundled fallback is EDN on the classpath (`resources/sample_players.edn`).

The auction-value scrape carries a trap of the same family, and it cost the board 33 priced players, the expensive end of it worst. FantasyPros puts the injury badge *inside* the name cell (`Puka Nacua (LAR - WR)<span class='injury-tag'>DTD</span>`), so reading that cell's whole text against an end-anchored name pattern parses nothing at all for precisely the players who carry knocks. `fantasypros/parse-aav` reads the cell's *own* text and matches the name unanchored — two guards rather than one, because they fail in opposite directions: a name wrapped in an `<a>` would defeat the first, a badge arriving as bare text rather than an element would defeat the second. Nothing caught it for a month because a source's hit rate is matched/rows — it grades the *join*, and a row the parser drops never reaches the join to be graded.

**League import** (`draft_day/ingestion/league_import.clj` + one namespace per provider, e.g. `league_import/sleeper.clj`, `league_import/espn.clj`) pulls a manager's real scoring/roster settings — and, for an auction draft, its budget — from a fantasy host, backend-proxied because ESPN needs the manager's own session cookies and the browser must not call a provider directly. It's a multimethod dispatch on `:provider` — `fetch-raw-league` (network) and `normalize-league` (pure) — rather than a protocol, matching the "one namespace per provider, called by name" convention `pipeline.clj` already uses for `sleeper.clj`/`espn.clj`/`fantasypros.clj`. Adding a provider is a new file with two `defmethod`s, a catalog entry, plus a `:require` in `routes.clj` for side-effecting registration; no change to the dispatcher itself.

The **network** multimethods across all three pairs take one request map — `{:league-id :season :credentials}` — rather than positional arguments, so a host that needs a season in its URL or a cookie on its request has somewhere to read them from; the pure normalizers stay positional, because a credential has no business reaching them. What that map holds is the *dispatcher's* contract and not a provider's: `import-league`/`sync-league`/`find-leagues` default the season, validate access, name the provider on the reply and coerce every roster id to a string, so no implementation has to remember to. That is `league-sync/unwrap-execution`'s argument — the first one that forgot would regress it silently — and the id coercion is the sharpest of them: `db/provider->player-id` builds a string-keyed crosswalk and `waiver/held-ids` maps a miss to itself, so a host publishing integer ids (ESPN does) would resolve none of them and hand back a board on which its whole league is free. `matchups` takes it too, with `fetch-matchups` holding the same contract (season defaulted, access validated): the scoreboard request adds the `:week` it is addressed by, and `current-week` takes the map as well, because ESPN's current week is on the league document. Both hosts have a matchup board; `providers/matchups?` is what tells the browser whether to offer the tab, so a host without one is neither offered nor asked.

`src/cljc/draft_day/providers.cljc` is the one description of a host — its label, the fields connecting to it needs, which are secret, and how to redact them — shared for `scoring.cljc`'s reason: the browser renders the connect form from it *synchronously*, before any request exists, and the server validates the map that form produces against the same table. `league-id-error` and `credential-errors` live there and are per-host, so the URL-path guard can loosen for one provider the day a non-numeric id arrives. Nothing may put a credential where it can be read back — a log line, an `ex-data`, an error body — except through `providers/redact`; ESPN's `espn_s2` is a live session token.

ESPN's league half (`league_import/espn.clj`, `league_sync/espn.clj`) carries three traps a fixture cannot see. It answers two ways that are not HTTP failures and must be treated as ones — a rejected cookie can arrive as an HTML login page with status 200, and a league the account cannot see as a 200 with no `:settings` — so every fetch names a `:require-key`; 401 and 403 stay distinct because they are different instructions (reconnect, versus this league is not yours). Team defenses are keyed by their **team abbreviation**, not their ESPN id: `player_ids/attach-ids` reads a player file with no defense rows, so `[:ids :espn]` has no entry for one and a defense keyed the ordinary way sits on the free-agent board while its owner holds it. Its D/ST scoring arrives as a *per-position override* (`pointsOverrides {:16 n}`) on a rule whose base weight is 0.0, so reading the base — right for the TE reception premium the same shape expresses — imports a league whose every defense projects zero; `league-import.espn/defense-only-stats` names the stats no skill player can accrue, and only those take the override. And ESPN's lineup slot 21 (IR) counts as neither a starter nor bench depth — counting it inflates `roster-size`, the single number `waiver/drop-candidate` asks to decide whether a claim costs a drop. Its defensive stat ids and its slot table are ESPN's documented numbering rather than a payload this repo has read; `test/draft_day/integration/espn_league_test.clj` is what confirms them against a live league, and skips out loud without credentials in the environment. Its ids have a gap a fixture cannot see either: `[:ids :espn]` comes from DynastyProcess, whose file maps only the rows it can reach from a Sleeper id and so lags on rookies — Trey Smack, a starting kicker, had an ESPN id and no Sleeper id there in September 2026, and drew as a bare `4869461` with no projection. So the sync and the matchup reply both carry `:provider-players`, ESPN's own name and position for every rostered player (a vector, since the browser keywordizes map keys), and `db/provider->player-id` resolves an id its column misses by name and position — only onto a player with no ESPN id of his own, and only when exactly one matches.

`ingestion/season.clj` holds `current`/`resolve-season`. Its own namespace because the dispatchers need it and are forbidden from requiring a provider, and because a year is a fact about the calendar rather than about Sleeper. It answers with the *calendar* year, which is the league year for ten months of twelve — so it is a default and never an override, and a caller holding a real season (a stored league entry, a request field) passes it.

nflverse (`nflverse.clj`) is the one enrichment source that joins *exactly* — on the GSIS id every universe player already carries — and the one that answers two questions from a single fetch: last season's realized usage, and games played across the last three seasons for the injury-risk scale. Re-downloading the newest season for the second question would be silly, so there is one task and one `:sources` label (`:nflverse/player-stats`). It ships `:nflverse/games-seasons` as a `{season length}` map rather than a bare list, because a consumer has to be able to tell a season the player missed from a season the *network* missed, and to size a gap without knowing the NFL calendar. `ingestion/espn_schedule.clj` is a second, unrelated ESPN reader: this week's kickoff times off the public scoreboard, keyless and ~40KB. It is a separate namespace from `espn.clj` on purpose — that one exists to survive a ~37MB response and carries its own `java.net.http` client, while this is a different endpoint at a different cadence, and sharing a `:sources` label and a TTL between them is what makes a thin column undiagnosable. It ships the ISO stamp rather than a formatted time, since the server does not know the manager's timezone, and `pipeline/assoc-kickoffs` joins it by **team** rather than by weekly line, so a player on bye gets no keys at all.

Its in-season sibling is `nflverse_weekly.clj`, reading `stats_player_week_{season}.csv` from the same release on the same exact GSIS key, but answering a different question: what a player has produced *this* season, his opportunity over the last `recent-window` weeks, and — from the highest REG week present — how far the season has got. Three things there are load-bearing. Its stat map is deliberately *wider* than `line-columns` (that one shows a history tile; this one scores a partial season under the league's own weights, so a weight with no column is a rule the in-season board cannot apply). `:games` counts the player's own rows, never weeks elapsed. And a missing file is week zero, not an outage — the asset 404s until week 1 is played, so every consumer must work with these columns entirely absent. It is deliberately not built on nflverse's weekly injury report: a player on season-ending IR drops off that report entirely (Malik Nabers played 4 games in 2025 and has zero "Out" weeks in it), so counting designations would rate the worst injury of the season as iron-man durable.

**Rankings engine** (`draft_day/rankings/`) is a numbered pipeline, split into a static half (computed once per scoring/roster config) and a live half (recomputed after every pick), orchestrated by `engine.clj`:

- `static-rankings`: `model` (stat line -> `:points`, via `rankings/model.clj`) -> `projections` (floor/ceiling band from expert-rank disagreement) -> `replacement` (replacement level) -> VORP -> `tiers` (gap detection above replacement) -> `injury` (the `:injury-risk` display signal) -> `pos-rank` (`rankings/pos_rank.clj`, the `RB1`/`WR2` identifier; static so it does not renumber as players are drafted)
- `live-valuation`: `value` (VBD -> stable salary-cap dollars) -> `inflation` / `inflation-index` (conserving inflation + per-position live market + phase decay) -> `worth`/`bargain` (Value scaled by live inflation, minus Worth). It also assocs a per-player `tcm` (tier-cliff multiplier, live/undrafted-only) — a display-only board signal, *not* an input to Value or Worth.

`rankings/injury.clj` is the second display-only signal and sits in the *static* half, since completed seasons and a preseason designation are not things a pick moves. `:injury-risk` is 1-5 from games missed per season over `min(3 fetched seasons, :sleeper/years-exp)`, floored at 5 by a serious current designation. Two things are load-bearing. The denominator is years in the league, not the width of the window — scored over a flat three seasons the most fragile players in football come out as last year's rookie class, who were not in the league for two of them. And it measures *availability*, not injury: the evidence is games played, so a benching counts like a hamstring, which is why the column's tooltip says "games missed" and never "injured". Like `tcm` it feeds nothing; market prices already carry the room's injury opinion, so discounting Worth by risk would charge a fragile player twice, and the PDM that was computed-but-never-consumed is the cautionary tale. `db/serious-injury-statuses` is the one copy of the serious-designation set, in cljc because the server floors on it and the board colours the Inj cell on it.

The scoring step is a multimethod dispatch (`rankings/model.clj`'s `score-board`, keyed on a `:model` keyword — `:points` by default, plain `draft-day.scoring/with-points`) rather than a hardcoded call, so a candidate formula validated in the benchmark harness (see below) ships by passing a different keyword into `static-rankings`, not by porting code out of the harness. `rankings/model/blend.clj` registers the ADP/ECR-blended and rookie-capital variants used there; none are wired to the live API today.

Valuation is hardwired to the Balanced weighting; there is no user-selectable strategy profile (the feature was removed — effective points equal raw points, VORP is not scarcity-adjusted, and inflation-sensitivity is fixed at 1.0). The positional-demand multiplier (PDM) that once rode alongside was removed too: it was computed on every pick but never fed Value or Worth.

Tiers are cut at a pool's biggest *absolute* gaps (`tiers/cut-points`), as many of them as its depth asks for at `tiers/TARGET-TIER-SIZE` players per tier, with `tiers/MIN-TIER-SIZE` forbidding a tier of one. This reverses two things the code used to say, so both are called out in `tiers.clj`: gaps are no longer ranked by *relative* drop (measured against the falling player, it grows without bound as points decay and drags nearly every cut into the tail — one 13-player top tier above four 2-player tiers, exactly backwards; the old objection to absolute gaps is answered by the pool already being truncated at replacement), and the count no longer follows the position's own cliff structure (it is sized, not counted, so a smooth position gets cut anyway — that is the trade a target size buys). `tcm` keeps a threshold and `tiers/relative-drop`; tiering no longer has a paired constant. Everything at or below replacement shares a final tail tier, and K/DST get a floor from `tiers/tier-floor` since they are absent from the replacement map.

`tiers/with-tiers` ships two scales side by side under `:tiers` — `:position` (cut on `:points` within a position) and `:overall` (cut on `:vorp`, the only score that compares a QB to an RB, with replacement at 0.0 so the whole below-replacement board is one tail tier). `:tier` stays as the flat alias for the positional one. Both are always computed, so the board switches scale on a position filter with no round trip. There is deliberately no strategy seam here — one technique, and FantasyPros' published tiers ride along as display columns rather than as a rival; `tiers.clj`'s docstring says where a seam would go if a second technique ever earns one. `:fantasypros/ecr-tier` no longer overrides the computed tier — it covers most of the board but not all of it, and it is an *overall* tier, so dense-ranking it alongside per-position cliff tiers merged two scales into one number. (It is format-scoped like the other FantasyPros columns, so it does follow the league's scoring; that is not why it was dropped.) It now rides along for the opt-in `:fp-tier` column, alongside `:fantasypros/ecr-pos-tier` — the finer tier each position's *own* cheatsheet cuts (RB 12, WR 13, TE 11, QB 8, K/DST 5 on the current sample, against 16 overall), scraped by `pipeline/pos-tier-tasks`. `fantasypros/pos-formats` is load-bearing there: QB/K/DST's `ppr-`/`half-point-ppr-` URLs 302 to the *overall* cheatsheet, so those three are fetched once and joined flat while RB/WR/TE are scoped per format.

**API** (`api/routes.clj`): `GET /api/players` returns the cached universe; `POST /api/rankings` takes scoring/roster config + `league-state` and returns the fully valued board (400 if the scoring config has no non-zero weights — an all-zero board is a lie, not a board); `POST /api/league/import` takes `{:provider :league-id :season :credentials}` and proxies to `league-import/import-league`, whose reply carries `:unsupported-scoring` — the league's own rules the vocabulary has no key for, which Settings shows rather than reporting a bare success. That list is short now: Sleeper states a tier or a bonus as a *stat* (`pts_allow_7_13` arrives as 1.0 in the week it happened), so a flat weighted sum expresses them exactly and the gap was never the model's shape but the twenty-nine keys it knew. What is left needs *two* weights rather than one more key — a position reception premium prices one stat by who caught it. `waivers-handler` runs `waiver-board-inputs` (score -> injury risk -> pos-rank) before `ros/with-ros`, because `:points`, `:injury-risk` and `:pos-rank` come from `engine/static-rankings` and nothing in `rankings.ros` produces them — without it the Risk, Pre and Pos columns render dead with nothing failing to say so. Only those three of the static stages, since the waiver board computes its own replacement and VORP on `:ros-points`. `without-projection-internals` then strips the working state the projections leave behind — `:ros/stats`, `:ros/games-remaining`, `:ros/games-played`, `:week/stats`, `:nflverse/recent`, `:realized/recent` and `:realized/season-to-date` — for the same reason `without-history` exists. `POST /api/waivers` takes scoring + roster config + a synced league and returns the free-agent pool valued in rest-of-season points, with `:lineup-upgrade`, `:upgrade`, `:walk-away`, `:bid`, `:win-prob`, `:bid-sure`, `:rivals`, `:competition`, `:trending/adds`, `:rostered` and `:claims-left` per player, and `:week`, `:week-fetched-at`, `:through-week`, `:season-games`, `:drop-candidate`, `:my-roster-players`, `:bidding` and `:trending` on the envelope — its rivals are priced from the league's bid history read off the server's disk cache by league id (`transactions/cached-history`), so it still makes no provider call and carries no credential; `POST /api/league/sync` takes the same body and proxies to `league-sync/sync-league`, and refuses a league whose sync names no provider rather than defaulting to Sleeper — a default would read an ESPN league through the Sleeper id map and report its whole roster as free. It refreshes the league's bid history beside the rosters (`transactions/bid-history`, below) and adds a summary of it as `:bid-history`, with `:bid-history-error` when the refresh failed — or had not finished within `routes/bid-history-wait-ms`, in which case the rosters go out beside what is cached and the refresh lands for the next sync. The Re-sync button's status says so. `POST /api/account/connect` takes `{:provider :credentials :season}` and proxies to `league-sync/find-leagues`; it is a POST and not a GET because an `espn_s2` in a query string reaches browser history, proxy logs and `Referer` headers, and it has no default provider because defaulting one meant a typo'd ESPN connect was looked up on Sleeper and came back "user not found". A host that identifies the manager but cannot list his leagues answers `:leagues-error` beside an empty list, so a discovery outage stops reading as an account that plays in nothing. Also serves the compiled SPA from `resources/public`.

### The in-season half

Draft-day dollars stop at the draft, and that line is the whole design. `value`, `inflation`, `tcm`, `worth`, `bargain` and `market` price a *whole roster* out of a fixed bankroll on one night; a waiver claim is a *single seat* against a budget spent down over months. So none of them appear on the waiver board, which is measured entirely in rest-of-season points. What is reused is the half that is about football rather than about an auction: `replacement/replacement-levels` and `with-vorp` already take a `score-key`, so they run on `:ros-points` untouched.

`rankings/ros.clj` blends the preseason projection with realized production, per stat key, on a per-game basis, and prorates over the games remaining. Writing the realized side as a *total* rather than as (games x per-game) cancels the division, which is what makes the expression total: at zero games played it collapses to the prorated preseason line with no branch — the right answer for a rookie who has not debuted, for every DST (nflverse publishes no DST row), and for the whole board in August. A player with no preseason line falls out of the same expression with a projected rate of zero, so a breakout is deliberately discounted early and climbs as games accumulate. A *stat* no preseason line carries looks identical and is not the same case: Sleeper's season line has no sub-forty field goal bucket while the realized line has them all, and shrinking those toward a zero no vendor ever asserted charged a kicker the breakout discount for a column nobody projects. `blend` reads the keys the preseason feed carries for anybody off the board itself — a hand-kept list of vendor gaps goes stale the moment either feed adds a column — which is why `with-ros` wants the whole universe and not a slice of it. The realized side is **Sleeper's own account where it arrived and nflverse's where it did not** — one or the other per player and never a mix, because the two count a first down and a blocked kick differently and a player scored half from each is scored in neither vocabulary. `ingestion/sleeper_actual.clj` is the Sleeper half: one request per week played, held to Sleeper's limit by `sleeper_http`, accumulated into `:realized/season-to-date`, `:realized/recent` and `:realized/game-log`. It is preferred for three measured reasons — nflverse publishes no team defense row *at all*, so a defense's realized production was permanently empty and the tier rules that are a third of its score had no realized side to land on; nflverse's first downs read higher than Sleeper's on a quarter to three quarters of the player-weeks either side reports, and it files a blocked field goal under `fg_blocked` where Sleeper counts it a miss; and it publishes no count of a touchdown's length at all. Scored under a league's own rules, Sleeper's line reproduces Sleeper's own per-player points exactly, which is what makes the player detail modal's week-by-week points agree with the league to the cent — that table being the one place the app states a realized number of its own rather than reporting the provider's. `:through-week` deliberately stays nflverse's answer alone: `ros` leans on it and the realized columns being unable to disagree, and two sources for the week is how a November league comes to read an August board. `PRIOR-GAMES` is chosen, not measured; `dev/` is where it would earn a number. Weeks left are not games left (17 games across 18 weeks), and `season-games` is passed in rather than known here so `rankings` keeps no NFL calendar of its own — `nflverse/games-in-season` is the one copy.

`:through-week` rides on the universe *envelope*, not on players: it is one fact about the league year, needed once per request. It and the in-season columns come from the same fetch, so they cannot disagree — a missing weekly file reads as week 0 *and* as no realized production, and the board degrades to the preseason board rather than to a November league priced on an August projection.

`rankings/waiver.clj` answers five things. Every reader of a roster goes through `waiver/held-ids` (implemented as `db/held-ids`, in cljc so the browser reads rosters through the same translation), because the second reader is what went wrong once: the availability filter translated its provider ids and the drop candidate did not, so no real league resolved a droppable player and every upgrade was measured against a floor of zero — invisible in tests whose fixture made the crosswalk an identity. `:active-ids` (players minus IR minus taxi) is what a seat count and a drop are drawn from; `:player-ids` is what availability is drawn from. `:lineup-upgrade` is the headline and what the board sorts on — what the claim adds to the *starting lineup*, seating the player and re-filling it (`rankings/lineup.clj`); it is absent rather than 0 when the league's seats are unknown, so "no lineup to compute against" cannot read as "adds nothing". `:upgrade` is the bench delta beneath it, measured against the player the manager can lose most cheaply — `waiver/drop-candidate` reads that off the starting lineup wherever the league's seats are known and falls back to worst-points only when they are not — because a claim costs a roster spot and not a positional slot (and 0 when a spot is already open); it stays signed, since most of a free-agent pool is worse than the man you would drop. `:walk-away` is what a player is worth to you: a conserving share of remaining FAAB over the best `claims-left` upgrades — that bound is read off the calendar, not chosen, and it is what makes it grow as the season shortens. The budget splits into two pools rather than one, since a single pool let bench depth outbid a starter: `waiver/stash-share` (0.15) is reserved for players with no lineup *gain* (`waiver/weights` branches on a positive `:lineup-upgrade`, so a zero or negative one stashes) and puts each player in exactly one pool, so a league with no lineup at all falls back to the pre-lineup rule with no special case. `:bid` is what to actually bid, set by `rankings/faab.clj` below. `$0` is a real FAAB bid (unlike the auction board's `$0`, which meant undraftable); `nil` means the league does not run FAAB or the budget is spent, and the two must not render the same. `:rival-max` is a fact, not a formula. `:trend` is display-only, on the `:injury-risk`/`:tcm` shelf. Replacement is computed over the whole board, never over the free agents, or it drifts down every time somebody is added.

`ingestion/league_sync.clj` mirrors `league_import.clj`'s multimethod convention but is a *separate* pair, because an import is a league's rules (yearly) and a sync is its state (every claim). Roster ids stay in the provider's space until `rankings.waiver` maps them through `db/provider->player-id`, where the universe is already in hand. Two traps live there: `parallel/all` wraps a thunk's throw in an `ExecutionException`, so the provider unwraps it or every 404 reports as a 502 (nothing in `pipeline` ever hit this because every task there is `best-effort`-wrapped); and the waiver type round-trips through the browser as a *string*, since `read-json-body` keywordizes keys and not values — `waiver/faab?` accepts both spellings, the same shape of fix `scoring/resolve-config` is.

`ingestion/transactions.clj` is a fourth pair, fetched *with* the sync but not part of it: every FAAB auction the league has run, the losing bids as well as the winning ones, which Sleeper publishes as `failed` waiver claims carrying their bids. It works a season at a time (`fetch-raw-season` / `normalize-season`), and each season names the one it continues (`:previous`), so the history reaches back a year without the dispatcher knowing how a host links its seasons; `:owner-id` rides on every bid because roster ids are per season. The seasons live in a server-side disk cache, one file per league-season under `transactions/cache-dir`, and never cross the wire: a sync refreshes an unfinished season, a finished one — the current one included — is read straight from the cache, a bid's owner is the claim's `creator` rather than the roster's owner at fetch time, the browser gets only `transactions/summary` (counts, fetch times and each manager's bidding profile), and the waiver board reads `transactions/cached-history` by league id — so `/api/waivers` still makes no provider call and carries no credential. A refresh that fails leaves the last good file in place and the sync reports `:bid-history-error` beside a summary of what is still cached. Which failed claims *lost* is decided structurally rather than from Sleeper's note text: a run's claims on one player with a completed claim among them are an auction, a run is its `status_updated` alone (every claim a run decides shares it to the millisecond), a failed bid above the winner failed on a roster rule and never competed, and one manager's several claims on a player are one bidder — his own duplicates also read "claimed by another owner", and in one real season counting them would have added 21 rivals who did not exist. `providers/bid-history?` says which hosts have a history to read; ESPN does not yet (`docs/TODO.md`).

`rankings/faab.clj` is the auction math, points-free, and it exists because the walk-away never looks at anybody else while FAAB is a blind first-price auction: the bid that makes a budget go furthest is just over the highest rival's. `waiver/rival-needs` measures what each rival's own lineup would gain from each free agent (his active roster through `held-ids`, his own drop, the league's seats), and `faab/with-market` takes it from there: each rival's claims a week, from his `bid-history` profile, are aimed by that need plus a CHOSEN share of value over replacement, with a Poisson count — a fixed count, `1 − (1 − share)^λ`, makes a rival with one target a certain bidder however rarely he bids. What he bids is `bid-prior/bid-share` for the predicted bidder count and the phase, scaled by position, budget and his `:log-multiplier`, his $0 rate moved on the log-odds scale, round-number heaps restored at `bid-prior/heaping`'s measured shares, capped at his `:faab-left` and floored at the league minimum. `:bid` is the value bid, `argmax P(win|b)·(walk-away − b)`, where a tie goes to the lower `:waiver-position` and is even odds when either is unknown; `:bid-sure` is the cheapest bid with a 90% chance; `:rivals` is the expected number of other bidders, and `:competition` holds the top rival bid's p50/p90 given somebody bids, the chance nobody does, and the likeliest three bidders. It is `:competition` and not `:market` because `:market` is already the draft board's dollar price — `:ros-vorp`'s reason. Sleeper's trending adds (`ingestion/sleeper_trending.clj`, the hundred most-added players over 48 hours, keyless, cached on its own hourly TTL and joined at request time by `pipeline/assoc-trending` on the Sleeper id; every live fetch also keeps a timestamped copy under `data/faab_cache/trending/`, since Sleeper keeps no past lists and those copies are all `faab/heat-weight` could ever be measured against) add to that interest, so the top of the list draws `faab/heat-weight` of what the rival's best target draws on need, need or no need — news no projection has caught up with, which a multiplier could not reach since a backup whose starter just went down has no need and no value over replacement yet; an empty answer counts as a failed fetch, a failure backs off before Sleeper is asked again, and under `DRAFTDAY_AS_OF_WEEK` there is no list, since today's is news a replayed week never had; a player off the list has no `:trending/adds` rather than zero, and the envelope's `:trending` says when the list was fetched, nil offline. A rival with no bid in the history gets `bid-history/silent-profile`, whose rate shrinks as the season runs on without a claim from him. Asking a lineup question of every rival would be eleven fills per free agent; `lineup/upgrades` answers a whole pool against one roster by skipping every candidate at or below his seat's floor, which provably cannot change a greedy fill. Every CHOSEN constant stands until the replay backtest scores it.

`bid_history.cljc` reads a league's history as a profile per manager — bids a week, share of bids at $0, aggression against his league — plus the league's own price level against the Sleeper-wide backbone in `bid_prior.cljc`, and a bidding style (sniper, big spender, $0 flyer, quiet, typical) for the League tab. Every figure is the league's weighted evidence blended with CHOSEN pseudo-bids at the prior's value, so a thin history reads as the typical Sleeper manager and a thick one as itself; the current season decays toward its latest week and last season counts at half. It is measured on the harness's own scale — bids a week over the weeks the league ran auctions, a bid's log ratio over the backbone's typical bid for its bidders and phase — which is why `bid-prior/phase` and `bid-prior/bucket` are the one copy of those cutoffs. The profiles ride on the sync summary as a vector, never a map keyed by manager: the browser keywordizes the keys it receives and a manager id is a number.

`ingestion/matchups.clj` is the **third** such pair, one cadence further along: an import is a league's rules (yearly), a sync is its state (every claim), a matchup is a live scoreboard (while you are looking at it). Folding it into the sync would serve Sunday-afternoon scores out of a Tuesday cache behind a button labelled Re-sync league. It normalizes to `{:week :matchups [{:matchup-id :roster-ids}] :scores {roster-id {:official :starter-ids :player-ids :player-points}}}`, carrying no provider vocabulary, and — like `league_sync` — leaves both roster ids and the player ids inside `:player-points` in the provider's space for `db/provider->player-id` to bridge. Three things are load-bearing. **The week is asked of the provider, never derived**: `:through-week` advances as games finish, so `(inc through-week)` asks for week N+1 while week N is being played, which for a price is stale and for a scoreboard is the wrong game — `docs/TODO.md` carries the same bug against the waiver board, which this deliberately does not change. **`:starter-ids` comes off the matchup document, not the roster**: the roster's is the lineup as it stands now, the matchup's is the lineup that counted, and they diverge exactly when somebody edits his lineup after the games lock. And **`players_points` arrives with keyword keys** — `draft-day.json/mapper` keywordizes every key it decodes, and these keys are player ids, so `{"4034": 18.4}` becomes `{:4034 18.4}` while the crosswalk holds strings; `matchups.sleeper/player-points` converts back, and without it the join misses the whole board and reads like a vendor publishing nothing. A week with no games is `[]` and a real answer, not a 404 — the `empty-is-missing? false` case `get-json`'s docstring exists for.

`rankings/matchup.clj`'s `optimal` reports each basis only when it can be acted on or believed. By projection it moves only players whose games have not started (`:locked?` rows keep their seats, and a bench player already playing cannot take one), because advice to make a swap the league will refuse is not advice. By actual it is nil until `week-final?` — every game on the side `STATUS_FINAL`, a side with no scoreboard at all being unknown rather than final — because before then a Thursday bench score is "left on the bench" in a seat whose starter plays Sunday. Each basis ships its seating (`:starters` with `:moved-in?`, `:bench` led by `:moved-out?`), and the matchup view draws it in place of the set lineup per side (`:lineup-view`, keyed by roster id, transient) rather than describing it in a box.

The seat vocabulary is `db/flex-slots` (`FLEX`, `WRRB_FLEX`, `REC_FLEX`, `SUPER_FLEX`) and `db/held-slots` (`BENCH`, `IR`, `TAXI`). A synced league now carries `:roster-positions` — its own seats, **in order**, in the app's spelling — because Sleeper's `starters` array is positional against that list and the count alone can never name which seat a starter occupies. `rankings/lineup.clj` fills narrowest-seat-first off `db/flex-slots`' set sizes rather than the old hardcoded "FLEX last", which is the same rule in a league whose only wide seat is FLEX and silently wrong in a superflex one. `WRRB_FLEX` and `REC_FLEX` together are the one non-nested case, where greedy is only near-optimal; that is a stated trade, not an oversight.

`matchups/espn.clj` reads one league document per week, and three of its traps were read off a live league rather than taken from ESPN's documentation. The `schedule` carries the *whole season* whatever week is asked for and ESPN fills `rosterForCurrentScoringPeriod` on the requested week's games alone, so what dates a game is the filled roster and not `matchupPeriodId` — those agree only while the week asked for is the current one. A side's score is `pointsByScoringPeriod` keyed by the week: `totalPoints` is 0.0 while the games are being played (`totalPointsLive` carries it) and `totalPointsLive` is nil once they are over, so neither total alone is this week's figure. And a player's applied total sits on the `playerPoolEntry`, a level below the roster entry whose own `appliedStatTotal` is nil. The seat trap is the structural one: an ESPN entry names its own seat on `lineupSlotId` while Sleeper's `starters` array is positional and `rankings.matchup` seats by index, so `matchups.espn/starter-ids` seats ESPN's entries into the league's own seat list *there*, padding an unfilled seat with `db/empty-seat` — the seats come from the `mSettings` fetched in the same document, which is the same vector `routes/matchup-slots` builds from the sync, so one reply's two halves cannot disagree about a league's shape. Teaching the shared board a second seating convention was the alternative.

`rankings/matchup.clj` puts two rosters side by side for one week. Everything is points, never dollars, for `rankings.waiver`'s reason. **Predicted and actual come from different places, deliberately**: `:week-points` is Sleeper's weekly line scored under the league's own weights, `:actual` is the provider's own number taken as given — not the same basis in a league whose rules the flat model cannot express, but the provider's figure is what the league *records*, and recomputing it from a model that cannot score half its rules would put the board in confident disagreement with the standings. **A zero before kickoff is not a zero**: `:actual` is nil until the player's game starts, decided from `:kickoff/started?`, which `pipeline/assoc-kickoffs` stamps so the ESPN status vocabulary stays in the namespace that owns it (no `rankings` ns requires `ingestion`). Absent means *unknown*, so a missing scoreboard shows the provider's number rather than blanking a completed week. **Optimal is drawn from the live roster less the sync's IR and taxi**, since a man on IR seated in an optimal lineup would report a gain nobody could have taken — the roster itself comes off the matchup document's `:player-ids`, because a sync goes stale on anyone's claim and a player picked up midweek would sit in the lineup while being unstartable. It is computed on *both* bases — `:week-points` is a decision (start him over him), `:actual` is regret — and `lineup/best-lineup` already takes a `score-key`, so it is two calls rather than two implementations; when each basis may be reported is `optimal`'s own paragraph, two above. The swaps are `:in`/`:out` lists rather than paired seats, because pairing asserts a correspondence a set difference does not carry. Two more: the bench is everyone who did not get a *seat*, derived from the seats rather than from the lineup list — with fewer slots than starters those come apart and a player would vanish off both halves; and `:teams` ships as a vector, since an integer map key round-trips through JSON as a string and returns keywordized.

`POST /api/matchup` (`routes/matchup-handler`) is the one endpoint that takes a *live* fetch on every request, because a scoreboard changes while you are looking at it. Its board pipeline is deliberately leaner than the waiver board's — no VBD, no rest-of-season blend, no vendor columns, since a matchup asks one week's question. `routes/matchup-slots` prefers the synced league's `:roster-positions` and falls back to `db/starting-slots` off the draft config, which is only a guess at this league's shape and cannot express a SUPER_FLEX seat — the fallback exists for a persisted sync written before that key did.

### Frontend: re-frame

Standard re-frame split: `db.cljc` (app-db shape, roster/team helpers, the column catalog — shared with the JVM so `lein test` reaches it, as are the other cljc namespaces: `scoring`, `providers`, `bio`, `confidence`, `game_log`, `stat_lines`, `ingestion.match`), `events.cljs`, `subs.cljs` (not read in detail — check before editing), `fx.cljs` (effect handlers: a small `fetch`-based `:http` effect, no extra HTTP deps; `:persist!` to localStorage; `:debounce` to coalesce a burst of the same event), `views/` (`header`, `board`, `team`, `waivers`, `roster`, `watchlist`, `controls`, `columns`, `compare`, `metrics`, `player_detail`, `player_stats`, `modal`, `settings`, `util`).

Flow: `:boot` merges persisted localStorage state into `default-db` -> `:fetch-players` (`GET /api/players`) -> `:recompute` (`POST /api/rankings` with the current `league-state`, built from `:teams`/`:drafted`/`:picks`) -> `:ranked-loaded` stashes the response under `:ranked`. Every mutating event (draft picks, config changes, column edits) re-dispatches `:recompute` so the board reflects live valuation immediately.

Each `:recompute` stamps a monotonic `:recompute-seq` that `:ranked-loaded` checks before writing: a full re-rank takes long enough that overlapping requests answer out of order, and without the check a reply computed under the *previous* scoring config could win and stick. The persisted localStorage slice is stamped with `fx/storage-version` and read back only under that exact stamp; anything else is discarded and the app opens at `default-db`. There is deliberately no in-place migration — bump the version whenever a persisted shape changes (a config key, an entry in either column catalog, a field on a team, a pick or a league entry, a value's type) and accept that a manager loses his layout, and mid-draft his picks, on that deploy. Four `reconcile-*` functions and the Sleeper→GSIS id crosswalk they needed were the alternative, and they amounted to a permanent record of every shape the app had ever written. `db/reconcile-league-sync` is the one that stayed, because it validates a provider's response rather than a shape we wrote (see Waivers below).

A `persist` interceptor (`events.cljs`) writes a whitelisted slice of db (`db/persist-keys`) to localStorage after any event that includes it — this is the only persistence; there's no server-side session.

**Accounts and leagues.** A manager plays in more than one league and across more than one host, so neither is a singular key, and an account is *his* rather than the host's. `:accounts` is keyed by `db/account-key` — `"provider:user-id"` — and `:leagues` by `db/league-key` — `"provider:league-id"`. Both are composite for the same reason one level apart: a league id is only unique within a provider, and keyed by provider alone a second login on one host silently replaces the first with nowhere to hang the several leagues it plays in. Both keys are opaque; nothing splits them, because an ESPN user id is a SWID full of braces and a host is free to use a colon tomorrow. Each league entry holds its `:name`, `:season`, `:my-roster-id`, its `:account-key`, its own `:config` (scoring, roster, team count are per league) and its `:sync` (the last `/api/league/sync` reply). `:active-league` names the one the whole app is about.

An account carries the `:credentials` that authorize reading its leagues, persisted, and only the league's *own* account authorizes a request about it (`db/credentials-for`). That is what killed the `:account` sub's fallback to whichever account happened to be connected — right while there is one and quietly wrong after that. `/api/waivers` deliberately sends none: it never re-contacts a provider, so a credential there is exposure on the hottest path in the app for nothing. An account key may be a React `:key` but never a DOM attribute — a SWID is half the credential pair.

`fx/:http` appends the HTTP status to a failure event, because a 401 and a 502 read identically at the handler otherwise and an expired cookie could only ever be reported as a generic sync failure. The *account* is marked stale rather than the app: a manager whose ESPN cookie expired must be sent to the ESPN card and left alone on his Sleeper one.

`:config` stays at the top of db as the *active* league's copy, so every existing consumer — the rankings request, the board, the scoring editor — reads one key and knows nothing about leagues. That copy is only safe while exactly one function writes it: `db/set-config` / `db/update-config` mirror into the active entry, and a writer that skipped the mirror would have its edit reverted, silently, by the next switch away and back. `:set-active-league` swaps the copy and re-runs **both** boards (`:recompute` and `:fetch-waivers`), because a switch that moved only the rosters would leave Worth priced under the league you left. It drops `:waivers` on the way — that board states *facts* about a league (who is rostered, your FAAB, the drop candidate) and under another league's name they are false, not stale — but keeps `:ranked`, which is stamped instead: `:ranked-loaded` records the `db/rules-stamp` its request carried, and `:board-rules-stale?` compares it to the live config. That separates the two staleness cases the old code conflated. A pick without its reply is a dollar or two out of date and stays readable, which is what `:recompute-failed` is for; a change of scoring, team count, bankroll or roster moves *every* column — points, VORP, the tiers, every dollar, and the vendor columns too, since `rankings.vendor` flattens ECR/ADP/AAV per scoring format — so `views/board/rules-banner` says so out loud. Stamping rather than clearing is what lets two leagues on the same format switch with no disruption, and what keeps the warning up when the recompute never lands.

Every reply that belongs to a league carries its key: `:sync-league` and `:import-league` thread `db/league-key` through `:on-success`, so a slow reply answering after the manager has switched writes into the league it was asked for rather than the one on screen. Settings' Connected Accounts card is the one place an account, a league or a team is *set* (`views/settings.cljs`); the header's `league-switcher` and the Waivers status line only read `:account`. Identity used to be settable in three places and readable in none.

Settings shows one section at a time (`db/settings-sections`, `:settings-section`, transient) behind a sidebar that badges what is waiting inside a section (`:settings-alerts`). It used to be one auto-fill grid, and a grid row stretches every card to its tallest neighbour — the scoring editor or a second account turned the small cards beside it into tall empty boxes. `[:set-view :settings section]` deep-links.

**Two halves.** `db/phase` says whether the active league is on draft day or in season: its own `:phase` override if set, else `:season` once `:through-week` is positive or the draft is done, `:draft` once the week is known to be zero, and **nil** until then — the week rides on the universe, and answering before it lands drew the draft half for a mid-season manager. Whose draft is the *host's*: a sync carries `:drafted?` (Sleeper's league `status`, ESPN's `draftDetail.drafted`), so a league drafted on its host opens in season on week 1's Sunday, and the tracker's `db/draft-complete?` speaks only for a league whose host said nothing, or for no league — read for every league, one tracker auction moved them all. `db/mode-views` lists each half's tabs (the first is where it opens), `db/phase-views` drops a Matchup tab the league's host has no board for (`providers/matchups?`; both hosts have one today), and the header draws the half of the tab on screen (`:mode`), so the board and its tabs stay up after the last pick until the manager moves on — the next thing he may want is to undo it. `:view` starts nil and the header draws neither half until `events/place-view` puts it on the phase's opening tab: at boot when stored data already decides the phase, else when the universe lands (or fails, falling back to draft day) — once, so a later universe reload never carries the manager off the board. After that only `:set-active-league` and `:set-phase`/`:switch-mode` move it. `:switch-mode` (the header's "Go to …" link) stores an override only when it disagrees with the data, so coming forward again returns a league to automatic; Settings' per-league select writes one explicitly. `views/header.cljs` holds the header so the node test build can reach it — `core` mounts a React root on load.

Draft state — `:teams`, `:drafted`, `:picks`, `:my-team-id` — is deliberately *not* per league yet; see `docs/TODO.md`.

The Waivers view (`views/waivers.cljs`) is a second board with its own column catalog (`db/waiver-column-catalog`), its own sort (`db/waiver-rank-key`, leading with Lineup, then Upgrade) and its own request stamp (`:waiver-seq`, the same out-of-order guard `:recompute-seq` is, with a worse symptom — a stale board says a player you just claimed is still free). It shares `:pos-filter` and `:search` with the draft board deliberately, and its `status-line` is one muted line — the week, when its projection was fetched, and what is missing — rather than a form: every input that sets identity lives in Settings, and Re-sync lives in the season header — which reports it on `:sync-status`, its own key, because two of the four season tabs render no status line and `:fetch-waivers` overwrites `:waiver-status` in the same turn a sync lands. FAAB is in that header. The Bid cell reads `$12 · 76%`, with its chance of winning in red below `waivers/priced-out`, and its title (`waivers/bid-title`) names the top rival bid, the likeliest rivals, the 90% bid against the walk-away, and where the prices came from. Sure and Max are tooltip lines rather than columns, and Rivals and Adds are columns, Adds credited to Sleeper under the board. `views/columns` is parameterized over a catalog rather than duplicated, so both boards share one set of drag mechanics; `waiver-column-catalog` is persisted state like `column-catalog`, so a column added to either one needs an `fx/storage-version` bump. `db/reconcile-league-sync` survives that deletion because it is not a migration: it validates a *provider's* response on the way in, and it may *discard* it — a sync is a cache of somebody else's state, re-fetchable in one click, so a bad shape costs a button press while a half-repaired one costs a board that believes the wrong people are rostered. Opening the tab fetches its board once, since that is a second full rank of the universe.

My Team (`views/team.cljs`) is where the season half opens: the synced roster full width. The roster is the `:my-roster` sub, which is the manager's own card off the League tab's `:league-rosters` rather than a second reading of the sync, so My Team, the Waivers panel and the League tab cannot disagree about whom he holds. Its rows are the `/api/waivers` reply's `:my-roster-players`, and the reply's `:drop-candidate` marks the seat a claim would cost. The server used to split the manager's roster itself (`waiver/my-roster`), and the two splitters had already drifted apart on who counted as a starter. Every season tab fetches the matchup on first open (`db/matchup-view?`), because the season header's week is only ever the matchup reply's; the tabs that read the waiver reply are `db/waiver-views`. Its side cards — This week, Lineup check, Best claims — answer from boards already fetched and link to the tab that says more; the first two read `:my-matchup`, the manager's own game, not whichever game the Matchup tab has picked.

The season half's League tab is `:rosters` (`views/league.cljs`), not `:league` — a view's half is read off its key, and the draft half's League tab is a different screen (the auction room's picks and bankrolls). It reads every synced team in the browser through `db/team-roster`, the only function that splits a roster into starters, bench and IR/taxi, which goes through `db/held-ids` and seats starters with `db/starter-seats`: a team's own `:starter-slots` where it names them (ESPN, whose lineup is not positional against `:roster-positions`), `:roster-positions` by index only for Sleeper, and no label otherwise. Each card tags its team's bidding style off the sync's `:bid-history` profiles (`:league-bid-profiles`, which turns `:style` back into a keyword, since it crosses JSON as a string), with `bid-history/style-line` as the tag's title and FAAB as a bare amount. A league whose host has no history carries no tag, while a manager who has never bid in one that does reads "No bids yet".

The Matchup view (`views/matchup.cljs`) is the third board and the one that is *not* a table of toggleable columns — it is a fixed two-sided layout, one row per lineup seat with the slot label down the middle, which is `views/compare`'s grid one scale up and for its reason: the comparison is the whole point of the screen. So it has no column catalog and nothing of its own in `persist-keys`. Projected is muted and actual is bold, because a projection is a claim and a result outranks it; **a dash is not a zero** — `:actual` is nil until kickoff, and rendering that as `0.00` would turn a Sunday morning into nine bad performances, which is what `.mu-a.pending` exists to keep apart. The bench is drawn dimmed rather than hidden, since a best lineup is drawn *in place of* the set one — a player it moves in marked ▲, a starter it benches leading the bench marked ▼ — and "start him" is not advice if the reader cannot see what he did.

`:matchup-pick` names **a roster id, not a matchup id**. A roster with no opponent carries a nil matchup id, which collides exactly with "nothing picked" — keying on it made a byed manager's own week both the default selection and the one game he could not pick. Switching games costs no round trip, since the server valued every roster in one reply. `:set-active-league` drops `:matchup` and `:matchup-pick` (the board states who you are playing and what he scored; under another league's name those are false, not stale) and refetches only while a season tab is on screen, since each of them shows its week — Settings and the draft half pick it up from `:set-view`'s first-open fetch, and this is the one board whose fetch is live.

**`rf/reg-sub` takes no docstring.** A string in that position is read as an input spec and registers a handler that cannot be derefed, with no compile error — so every sub in `subs.cljs` documents itself in a `;;` comment above the form.

The board is data-driven: `:columns` is an ordered vector of `{:key :visible?}` against `db/column-catalog`, so columns can be toggled/reordered without touching render code. A catalog change is a persisted-shape change, so it needs a `fx/storage-version` bump — see above.

Which tier scale the board shows is not a setting: `:board-players` resolves `:tier` from `[:tiers (db/tier-scale pos-filter)]`, shadowing the flat alias the server ships, so a position filter switches scale with no refetch and everything downstream (row striping, the legend, the Tier column, sorting) keeps reading one key. Rows are tier-striped in every view for the same reason — before the overall scale existed, striping was switched off unless filtered, because a tier 2 RB beside a tier 2 WR meant nothing.

`(:config :scoring)` is either a preset keyword (`:standard`/`:half-ppr`/`:ppr`) or, once a manager customizes or imports, a full `{stat-key weight}` map — mode is derived (`:scoring-mode` sub), never stored separately. A *connected* league's settings are not editable at all: scoring, roster, team count and — once an import has supplied one — the auction budget are whatever its import said. `db/league-owned-keys` is the one statement of that set; Settings and the Start Draft modal draw those keys read-only off it, and hand edits go through `:edit-config`, which drops them (`:apply-config` stays the import's own path). An editable copy is what kept Re-sync from refreshing the rules, so Re-sync (`:refresh-league`) now re-imports alongside the roster sync, and an import that changes nothing applies nothing — no re-rank for a button pressed after every claim. What the import could not apply, whether it brought a budget, or why it failed is stored on the league entry as `:rules`, persisted, so the warning outlives a reload; a failure is assoc'd beside the last good import rather than replacing it, since those settings are still the ones in force. A failed import says the board is still on the previous settings rather than passing them off as this league's, and there is deliberately no hand-edit escape hatch. Coercing that field to a weight map is `scoring/resolve-config`, used by both `routes/resolve-scoring` and the `:scoring-format` sub: the browser derives which vendor format its league reads from the same field the server does, and hand-written copies of that `cond` had already drifted on the string spellings. The preset table and `stat-keys` live in shared `src/cljc/draft_day/scoring.cljc` so the editor can seed a custom map synchronously; there is deliberately no endpoint serving them, because seeding from an async fetch is what used to write a nil scoring config. `stat-keys` is every rule a host exposes (88 of them) while a preset prices only the twenty-nine a named format is about — `scoring/stated-only` is the rest, at 0.0, so Standard/Half/PPR stay byte-identical and an import still has a key to land every rule on. `scoring/unprojected-stats` is then the keys *neither* projection horizon carries, which is what the editor greys out and what `scores-anything?` refuses to count. One set and not two, because the season-line fill below makes a weekly-only key reach the draft board like any other — which is also why `:ff`, `:def_td` and `:safe` are no longer in it. Field goals are scored *by distance*, because every host scores them that way and the grids differ — Sleeper splits everything under forty into three buckets and stops at 50+, ESPN uses one band under forty and splits 50-59 from 60+ — so `scoring/fg-buckets` names the made-kick keys and the flat `:fgm` yields to any of them that carries a weight (`sleeper/scored-stats` publishes both, and weighting both pays for one kick twice). The two Sleeper projection lines disagree about which buckets they publish — the weekly carries every make under fifty, the season the two over forty — so ingestion carries both sets and each line scores what it has; that is what makes the board agree with Sleeper's own totals on both (Aubrey 118 against 116 for a season, Bass 6.96 against 6.85 for a week). Everything *else* the season line is silent about is filled from the week-one line instead (`sleeper/complete-season-line`), scaled by that player's own implied games — `pts_ppr` season over `pts_ppr` week, clamped to seventeen because the two horizons disagree hard about a marginal player and an unclamped ratio reached thirty. Without it, widening the vocabulary is not a neutral gain but a tilt: the buckets the season line does publish are receiving ones, so receivers and tight ends gain and quarterbacks and defenses do not, and VORP compares those directly. Filled, a starting quarterback gains about 8 points a season and a starting defense about 72 — three quarters of what it was reading — while receivers barely move. Made field goals are exempt and that carve-out is load-bearing: the two horizons *disagree* about that grid rather than covering different parts of it, and filling one from the other read Aubrey as thirty-one makes against the seventeen his season line states, scoring him 160 against Sleeper's 116. A player Sleeper projects no week for keeps the sparse line, which is a third of the universe and none of the top of it. `db/scoring-catalog` groups the stat keys for the custom editor in `views/settings.cljs` — ten groups now, each with `:stats` (what a named format is about, always drawn) and `:more` (everything else a host exposes, behind a `<details>` that opens when the league puts a weight inside it). Eighty-eight fields in one grid is a worse editor than twenty-nine was, and every rule in `:more` is zero in a league that has not imported one; the tier families are entirely `:more`, so a manager hand-rolling a PPR league never sees them. Presentational metadata only, not the same shape as `column-catalog` (flat, no grouping). `settings/import-warning` reports **two** states and not one, because collapsing them is what made the old warning confusing: a rule with no key scores nothing anywhere ("not modelled" — the position reception premiums, which price one stat by who earned it and so need two weights), while a rule the model holds that no projection carries still scores the weeks that have happened ("no projection" — it moves the in-season boards and cannot move the draft board). The sidebar badge counts only the first. League import (`:import-league` in `events.cljs`) POSTs to `/api/league/import` rather than calling a provider's API directly from the browser — the shared `fetch`-based `:http` effect (`fx.cljs`) checks `resp.ok` and routes any non-2xx to `on-failure` with the body's `:error`.
