# CLAUDE.md

Fantasy football auction-draft assistant (VBD-based). Backend: stateless JSON API. Frontend: ClojureScript/re-frame SPA, all draft state lives in browser. Also includes in-season Waivers (league sync, re-projection, FAAB pricing).

## Commands

**Backend** (`lein`):
- `lein repl`, `lein test`, `lein test :only ns/fn`, `lein test :integration`, `lein run` (server on $PORT)
- Tests stub fetchers at namespace boundary; `test/draft_day/integration/` hits live vendors, skips without `DRAFTDAY_ESPN_*` env vars
- **JAVA_HOME**: `export JAVA_HOME=/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home` (shadow-cljs needs it)

**Frontend** (shadow-cljs with `:lein true`):
- `npm run watch` (port 8280), `npm run release`, `npm test` (cljs-only: `events`, `subs`, `waivers`, six `views/*`)

**Env vars**: `DRAFTDAY_OFFLINE=1`, `DRAFTDAY_CACHE_TTL_HOURS` (24), `DRAFTDAY_WEEKLY_TTL_HOURS` (1), `DRAFTDAY_REALIZED_TTL_HOURS` (1), `DRAFTDAY_TRENDING_TTL_HOURS` (1), `DRAFTDAY_NEWS_TTL_MINUTES` (15), `DRAFTDAY_INJURY_TTL_HOURS` (3), `DRAFTDAY_AS_OF_WEEK=N` (replay week N), `DRAFTDAY_ESPN_SWID/S2/LEAGUE/SEASON` (integration only)

**Research harnesses** (`dev/`, `:dev` profile, active by default):
- `benchmark.report`: score model vs historical outcomes
- `replay.report`: compare Worth vs actual picks
- `faab.replay`: score FAAB model on real auctions
- `faab.interest`: fit weights to real claims (11 leagues)
- `faab.sweep`: score FAAB constants one at a time
- `faab.report`: what Sleeper leagues actually pay

## Architecture

**Stateless design**: Backend caches only provider data (players universe, weekly line, bid history) on disk. All draft state lives in browser, round-tripped to `/api/rankings` on every request. Rankings engine: pure function of `(players, scoring, roster-config, league-state)`.

### Backend: Ingestion

Universe cache: `offline-sample -> fresh-cache -> live -> stale-cache -> bundled-sample`. Base (Sleeper, keyless) + best-effort joins (FantasyPros ECR/auction via Jsoup, ESPN AAV via `java.net.http`). Fetches concurrent, joins sequential. Per-vendor rate limits in `fantasypros/fetch-page` and `sleeper_http.clj`. **Format-scoped columns** (ECR, ADP): fetched for all three formats, stored `:vendor/by-format`, flattened at request time per league's format. **No format fallback** — PPR assumed at ingestion would silently wrong a STANDARD league. Cache versioned (`v15.transit`, `v4.transit`, `v2.transit`); old files not found.

**FantasyPros name scrape trap**: injury badge inside name cell defeats end-anchored pattern. `parse-aav` reads cell text unanchored + checks element structure (two guards failing opposite ways). Hit rate grades the join, not the parse.

### League import/sync/matchup

Three multimethod pairs on `:provider`: `import-league` (yearly rules), `sync-league` (state per claim), `find-leagues` (discover), `matchups` (live scoreboard). Each takes `{:league-id :season :credentials}` so a host needing season in URL or cookies has one place to read from. Pure normalizers are separate. Dispatcher handles defaults, validation, roster id string coercion, provider naming.

**ESPN traps**: (1) Defense keyed by **team abbr, not ESPN id** — no entry in id crosswalk, sits on free-agent board. Defense scoring as points override on 0.0-weight rule; read with `db/serious-injury-statuses`. (2) **Slot 21 (IR) not a depth**: seat count inflates; only include in drop calculation. (3) **Roster alignment**: `player_ids` in matchup as keywords; reconvert to strings. (4) **DynastyProcess id lag on rookies**: sync carries `:provider-players` (name+pos); `db/provider->player-id` resolves misses by name/pos, only when one match exists. (5) **"Rejected" as 200 HTML + "not seen" as 200 no `:settings`**: use `:require-key` on every fetch.

`src/cljc/draft_day/providers.cljc`: one host description (label, fields, redaction). **Credentials never logged/in ex-data/in error body except through `providers/redact`**. ESPN's `espn_s2` is a live session token.

### Other ingestion sources

**nflverse**: joins exactly on GSIS id; answers two Qs from one fetch (last season's usage + games over 3 seasons for injury risk). Ships `:nflverse/games-seasons` as `{season length}` map to distinguish missed season from network miss.

**ESPN schedule**: keyless, ~40KB, separate namespace from `espn.clj` (different endpoint, cadence, client). Ships ISO stamp; joins by team (players on bye get no keys).

**ESPN news** (`ingestion/espn_news.clj`, `GET /api/players/:id/news`): fetched per card open, not with the universe (GET is fine, no credential). Fantasy news feed only (Rotowire items, newest 10, tags stripped); the injury designation is Sleeper's (see Sleeper injuries). Reply `{:news :fetched-at :errors}`; a failed feed lands in `:errors`. In-memory cache per ESPN id, TTL `DRAFTDAY_NEWS_TTL_MINUTES`, errored replies never cached; empty offline. No ESPN id (DynastyProcess lags on rookies) = 200 `{:reason :no-espn-id}`, unknown player = 404.

**nflverse_weekly**: `stats_player_week_N.csv`, answers this season's production + opportunity + season progress. Stat map wider than line-columns (scores under league's own weights). `:games` counts player rows, not weeks. Missing file = week 0, not outage. **Not built on injury report** — IR players drop off that report entirely, so designations would mislabel them durable.

**Sleeper injuries** (`ingestion/sleeper_players.clj`): the projections feed's embedded `:injury_status` is stale, so `routes/universe` replaces `:sleeper/injury-status` (plus body part, notes, updated-at) from Sleeper's `/v1/players/nfl`, kept apart on its own TTL through `pipeline/load-ttl-cache` (fresh, else live, else stale with backoff; trending adds use it too). Complete per fetch: a player the list omits is healthy and his status is cleared. Nil offline or replaying a week, which keeps the feed's value.

**Season resolution** (`ingestion/season.clj`): calendar year = league year for 10 of 12 months, is default never override.

### Rankings engine

**Static half** (computed once per scoring/roster config): `model` (stat → `:points`) → `projections` (floor/ceiling from expert disagreement) → `replacement` → VORP → `tiers` → `injury-risk` → `pos-rank` (RB1/WR2; stays same as drafted).

**Live half** (after every pick): `value` (VBD → salary-cap $/stable) → `inflation` (conserving + per-position market + phase decay) → `worth`/`bargain`, `tcm` (tier-cliff multiplier; display only).

**Injury risk** (static, display-only): 1-5 from games missed per season / years-in-league (min 3 seasons), floored at 5 by serious designation. Measures availability (games played), not injury. Does not feed Value/Worth (market prices carry injury already). `db/serious-injury-statuses` in cljc (server + browser both use).

**Scoring**: multimethod dispatch on `:model` keyword (`:points` default). Candidate models from benchmark harness register in `rankings/model/blend.clj`; ship by keyword, not code porting.

**Tiers**: cut on absolute gaps (not relative drop) at `:tiers/TARGET-TIER-SIZE` players/tier, min `:MIN-TIER-SIZE`. Sized, not counted (smooth position still cut). Below replacement = one tail tier. Two scales: `:position` (points per pos) + `:overall` (VORP). **FantasyPros pos-tier scrape trap**: QB/K/DST URLs 302 to overall cheatsheet; fetch once + join flat, RB/WR/TE per format.

### API

- `GET /api/players`: cached universe
- `POST /api/rankings`: scoring + roster config + league-state → valued board (400 if all-zero scoring)
- `POST /api/league/import`: `{:provider :league-id :season :credentials}` → `:unsupported-scoring` in reply
- `POST /api/waivers`: scoring + roster config + synced league → free-agent pool in ROS points. Per-player: `:lineup-upgrade`, `:upgrade`, `:walk-away`, `:bid`, `:win-prob`, `:rivals`, `:competition`, `:trending/adds`, `:rostered`, `:claims-left`, `:season-*`. Envelope: `:week`, `:through-week`, `:drop-candidate`, `:my-roster-players`, `:bid-history` (cached by league id, no provider call).
- `POST /api/league/sync`: same body → rosters + bid-history refresh. **No default provider** (would misread ESPN as Sleeper). `:bid-history-error` if refresh fails/times out; rosters go out with cached history. Re-sync button shows status.
- `POST /api/account/connect`: `{:provider :credentials :season}` → leagues via `league-sync/find-leagues`. **POST not GET** (espn_s2 in query reaches history/logs). **No default provider** (typo'd ESPN was looked up as Sleeper → "user not found").
- Waivers handler: run `:points`, `:injury-risk`, `:pos-rank` (from static) before `with-ros` (waiver board scores on `:ros-points`). Strip projection internals before respond.
- Serves SPA from `resources/public`.

### In-season: ROS blend

Draft dollars stop at draft; waiver claims are measured in ROS points only (value/inflation/tcm/worth/bargain hidden). Reuses football half (replacement/VORP) via `:ros-points`.

`rankings/ros.clj`: blends preseason + realized per-stat on per-game basis, prorates games remaining. Realized as *total* (not games × per-game) so the expression collapses to preseason at zero games (right for rookies, DST, August board). **Sleeper's realized where available, nflverse otherwise** (one source per player, never mixed). Why Sleeper: (1) nflverse has no DST rows at all; (2) first-downs count differs ~1/4 of player-weeks; (3) no TD length. Sleeper's score reproduces league totals exactly (player detail week-by-week agrees to cent). **`:through-week` stays nflverse only** (ros leans on realized columns being unable to disagree; two sources = Nov league on Aug projection).

`:through-week` on universe envelope (one fact/request, game-day cadence; don't drift off old cache). Separate 1-hour cache for realized (fetched with every req, cached separately). Missing weekly file = week 0 + no realized (board degrades to preseason). `season-games` passed in (rankings has no NFL calendar).

### Waiver board  

`rankings/waiver.clj`: `:lineup-upgrade` (headline, sorts board), `:upgrade` (bench delta), `:walk-away` (share of remaining FAAB), `:bid` (model bid), `:bid-sure` (90% win), `:rivals` (count), `:competition` (p50/p90/nobody). Budget split: 85% lineup gain / 15% stash. Walk-away capped at `faab/market-cap`.

Transactions (`ingestion/transactions.clj`): FAAB auctions per season, disk-cached per league-season (never sent to browser). `transactions/summary` only (counts + bidding profiles). Browser reads cached history by league id (no provider call in `/api/waivers`).

**FAAB model** (`rankings/faab.clj`): conditional logit of rival utility (measured on real claims), Poisson count. **Shared features** (all rivals): last week, season so far, VORP, position, recently dropped. **Rival own**: would he start. Bids stack via gamma draw; bid = argmax utility × (walk-away − bid). Sleeper trending adds to utility (1-hour cache). **Backtest** (11 leagues): fitted interest + spread cut who-bids loss 38%, win-chance 61% vs hand-set.

### Matchups

**Fetch strategy**: three cadence-related pairs. Import (yearly rules) → Sync (state per claim) → Matchup (live scoreboard). **Week asked of provider, never derived** — `(inc through-week)` while week N plays is stale/wrong game. **`:starter-ids` off matchup document, not roster** (synced rosters stale on claims). **`player_points` comes as keyword keys** — `{"4034": 18.4}` → `{:4034 18.4}`; must reconvert. Week with no games = `[]` (real answer, not 404).

**ESPN matchup traps**: (1) `schedule` is whole season; `rosterForCurrentScoringPeriod` only for requested week — use filled roster, not `matchupPeriodId`. (2) Score keyed by week: `totalPoints` = 0.0 during games, `totalPointsLive` during, nil after — take `totalPointsLive` or `totalPoints`. (3) Score on `playerPoolEntry`, not roster entry. (4) Seat trap: `lineupSlotId` vs positional; seat by index into league's `:roster-positions`.

**Optimal lineups** (`rankings/matchup.clj`): By projection, move only unlocked players. By actual, nil until week-final (all games `STATUS_FINAL`). Predicted from `:week-points` (decision), actual from provider (regret). **Optimal drawn from live roster minus IR/taxi** (can't count a gain on a dropped/IR player).

`POST /api/matchup`: live fetch every request (scoreboard changes while viewing). Lean pipeline (no VBD/ROS/vendor columns). Seats prefer synced `:roster-positions`, fallback to `starting-slots`.

### Frontend: re-frame

Standard re-frame split: `db.cljc` (app-db shape, roster/team helpers, the column catalog — shared with the JVM so `lein test` reaches it, as are the other cljc namespaces: `scoring`, `providers`, `bio`, `confidence`, `game_log`, `stat_lines`, `ingestion.match`), `events.cljs`, `subs.cljs` (not read in detail — check before editing), `fx.cljs` (effect handlers: a small `fetch`-based `:http` effect, no extra HTTP deps; `:persist!` to localStorage; `:debounce` to coalesce a burst of the same event), `views/` (`header`, `board`, `team`, `waivers`, `roster`, `watchlist`, `controls`, `columns`, `compare`, `metrics`, `player_detail`, `player_stats`, `modal`, `settings`, `util`).

Flow: `:boot` merges persisted localStorage state into `default-db` -> `:fetch-players` (`GET /api/players`) -> `:recompute` (`POST /api/rankings` with the current `league-state`, built from `:teams`/`:drafted`/`:picks`) -> `:ranked-loaded` stashes the response under `:ranked`. Every mutating event (draft picks, config changes, column edits) re-dispatches `:recompute` so the board reflects live valuation immediately.

Each `:recompute` stamps a monotonic `:recompute-seq` that `:ranked-loaded` checks before writing: a full re-rank takes long enough that overlapping requests answer out of order, and without the check a reply computed under the *previous* scoring config could win and stick. The persisted localStorage slice is stamped with `fx/storage-version` and read back only under that exact stamp; anything else is discarded and the app opens at `default-db`. There is deliberately no in-place migration — bump the version whenever a persisted shape changes (a config key, a field on a team, a pick or a league entry, a value's type) and accept that a manager loses his picks mid-draft on that deploy. Four `reconcile-*` functions and the Sleeper→GSIS id crosswalk they needed were the alternative, and they amounted to a permanent record of every shape the app had ever written. The column layouts are the one exception: `fx/load-persisted` keeps `:columns` and `:waiver-columns` across a bump and `:boot` runs them through `db/reconcile-columns` (his order and choices kept, a new column inserted after the one it follows in the catalog, a dropped one dropped), because a layout is a preference the manager built by hand and a catalog change is routine. `db/reconcile-league-sync` is the one that stayed, because it validates a provider's response rather than a shape we wrote (see Waivers below).

A `persist` interceptor (`events.cljs`) writes a whitelisted slice of db (`db/persist-keys`) to localStorage after any event that includes it — this is the only persistence; there's no server-side session.

**Accounts and leagues.** A manager plays in more than one league and across more than one host, so neither is a singular key, and an account is *his* rather than the host's. `:accounts` is keyed by `db/account-key` — `"provider:user-id"` — and `:leagues` by `db/league-key` — `"provider:league-id"`. Both are composite for the same reason one level apart: a league id is only unique within a provider, and keyed by provider alone a second login on one host silently replaces the first with nowhere to hang the several leagues it plays in. Both keys are opaque; nothing splits them, because an ESPN user id is a SWID full of braces and a host is free to use a colon tomorrow. Each league entry holds its `:name`, `:season`, `:my-roster-id`, its `:account-key`, its own `:config` (scoring, roster, team count are per league) and its `:sync` (the last `/api/league/sync` reply). `:active-league` names the one the whole app is about.

An account carries the `:credentials` that authorize reading its leagues, persisted, and only the league's *own* account authorizes a request about it (`db/credentials-for`). That is what killed the `:account` sub's fallback to whichever account happened to be connected — right while there is one and quietly wrong after that. `/api/waivers` deliberately sends none: it never re-contacts a provider, so a credential there is exposure on the hottest path in the app for nothing. An account key may be a React `:key` but never a DOM attribute — a SWID is half the credential pair.

`fx/:http` appends the HTTP status to a failure event, because a 401 and a 502 read identically at the handler otherwise and an expired cookie could only ever be reported as a generic sync failure. The *account* is marked stale rather than the app: a manager whose ESPN cookie expired must be sent to the ESPN card and left alone on his Sleeper one.

`:config` stays at the top of db as the *active* league's copy, so every existing consumer — the rankings request, the board, the scoring editor — reads one key and knows nothing about leagues. That copy is only safe while exactly one function writes it: `db/set-config` / `db/update-config` mirror into the active entry, and a writer that skipped the mirror would have its edit reverted, silently, by the next switch away and back. `:set-active-league` swaps the copy and re-runs **both** boards (`:recompute` and `:fetch-waivers`), because a switch that moved only the rosters would leave Worth priced under the league you left. It drops `:waivers` on the way — that board states *facts* about a league (who is rostered, your FAAB, the drop candidate) and under another league's name they are false, not stale — but keeps `:ranked`, which is stamped instead: `:ranked-loaded` records the `db/rules-stamp` its request carried, and `:board-rules-stale?` compares it to the live config. That separates the two staleness cases the old code conflated. A pick without its reply is a dollar or two out of date and stays readable, which is what `:recompute-failed` is for; a change of scoring, team count, bankroll or roster moves *every* column — points, VORP, the tiers, every dollar, and the vendor columns too, since `rankings.vendor` flattens ECR/ADP/AAV per scoring format — so `views/board/rules-banner` says so out loud. Stamping rather than clearing is what lets two leagues on the same format switch with no disruption, and what keeps the warning up when the recompute never lands.

Every reply that belongs to a league carries its key: `:sync-league` and `:import-league` thread `db/league-key` through `:on-success`, so a slow reply answering after the manager has switched writes into the league it was asked for rather than the one on screen. Settings' Connected Accounts card is the one place an account, a league or a team is *set* (`views/settings.cljs`); the header's `league-switcher` and the Waivers status line only read `:account`. Identity used to be settable in three places and readable in none.

Settings shows one section at a time (`db/settings-sections`, `:settings-section`, transient) behind a sidebar that badges what is waiting inside a section (`:settings-alerts`). It used to be one auto-fill grid, and a grid row stretches every card to its tallest neighbour — the scoring editor or a second account turned the small cards beside it into tall empty boxes. `[:set-view :settings section]` deep-links.

**Two halves.** `db/phase` says whether the active league is on draft day or in season: its own `:phase` override if set, else `:season` once `:through-week` is positive or the draft is done, `:draft` once the week is known to be zero, and **nil** until then — the week rides on the universe, and answering before it lands drew the draft half for a mid-season manager. Whose draft is the *host's*: a sync carries `:drafted?` (Sleeper's league `status`, ESPN's `draftDetail.drafted`), so a league drafted on its host opens in season on week 1's Sunday, and the tracker's `db/draft-complete?` speaks only for a league whose host said nothing, or for no league — read for every league, one tracker auction moved them all. `db/mode-views` lists each half's tabs (the first is where it opens), `db/phase-views` drops a Matchup tab the league's host has no board for (`providers/matchups?`; both hosts have one today), and the header draws the half of the tab on screen (`:mode`), so the board and its tabs stay up after the last pick until the manager moves on — the next thing he may want is to undo it. `:view` starts nil and the header draws neither half until `events/place-view` puts it on the phase's opening tab: at boot when stored data already decides the phase, else when the universe lands (or fails, falling back to draft day) — once, so a later universe reload never carries the manager off the board. After that only `:set-active-league` and `:set-phase` move it; the one way to cross halves by hand is Settings' per-league phase select, which writes an override explicitly. `views/header.cljs` holds the header so the node test build can reach it — `core` mounts a React root on load.

Draft state — `:teams`, `:drafted`, `:picks`, `:my-team-id` — is deliberately *not* per league yet; see `docs/TODO.md`.

The Waivers view (`views/waivers.cljs`) is a second board with its own column catalog (`db/waiver-column-catalog`), its own sort (`db/waiver-rank-key`, leading with Lineup, then Upgrade) and its own request stamp (`:waiver-seq`, the same out-of-order guard `:recompute-seq` is, with a worse symptom — a stale board says a player you just claimed is still free). It shares `:pos-filter` and `:search` with the draft board deliberately, and its `status-line` is one muted line — the week, when its projection was fetched, and what is missing — rather than a form: every input that sets identity lives in Settings, and Re-sync lives in the season header — which reports it on `:sync-status`, its own key, because two of the four season tabs render no status line and `:fetch-waivers` overwrites `:waiver-status` in the same turn a sync lands. FAAB is in that header. The rows are kept Sleeper-simple and the detail lives on the player card: by default #, Player, Pos (his rank at his position on fantasy points so far, `:season-pos-rank`, the preseason rank before week 1), Tm, Bye, Wk (this week's projection, the only projection on a row), Pts, Avg, GP, Bid, Rivals, Adds, Risk and Inj, sorted by Adds descending — the players off Sleeper's trending list follow in # order (`db/waiver-rank-key`), and # keeps its own ranking whatever the sort; every other column is one click away in the picker. The player card (`views/player_detail.cljs`) is where the detail lives, ordered to decide a claim: Bidding first (the Bid popover's content, `player-detail/bidding-rows`), the claim band, the season stats — in season the table's last column is the season so far rather than the season projection (`stat-lines/stat-table` with `:in-season?`) — the week-by-week log, then the projection and evidence. The Bid column is the typical winning bid (`faab/typical-bid`, the median highest rival bid) with its chance, `$4 · 49%`, and its popover leads with the suggested value bid. The Suggested-bid column (`:bid`) reads `$12 · 76%`, with its chance of winning in red below `waivers/priced-out`, and its hover popover (`waivers/bid-tip-popover`, the app's own rather than a `title`, which the browser draws at its own small size; fixed to the viewport so the board's scroll container cannot clip it) shows `waivers/bid-title`, which names the top rival bid, the likeliest rivals, the 90% bid against the walk-away, and where the prices came from. Sure and Max are tooltip lines rather than columns, and Rivals and Adds are columns, Adds credited to Sleeper under the board. While `db/bid-predictions?` is false (the bid model is on hold) the UI offers none of Typical, Bid or Rivals: `db/waiver-columns-for` removes them in every league, so the picker, the compare tile, the player card's bidding band and Best claims' `$bid` suffix omit them while `/api/waivers` still prices bids, and a stored layout keeps them for the day the flag flips. Otherwise, in a synced league that does not run FAAB, `waiver-columns-for` hides Bid and Rivals (`db/faab-columns`) and greys them out in the column picker without touching the stored layout, so a FAAB league gets them back. An unsynced league has not said it doesn't bid, so nothing is hidden there. `views/columns` is parameterized over a catalog rather than duplicated, so both boards share one set of drag mechanics; `waiver-column-catalog` is persisted state like `column-catalog`; a column added to either reaches a stored layout through `db/reconcile-columns`, with no storage bump. Both boards pick columns from one dropdown checklist (`views/columns/picker`, two columns wide, grouped by `db/waiver-column-groups` on the waiver board, with a reset) and reorder them by dragging their own headers (`board/header-cell`, parameterized by the board's catalog and events). `db/reconcile-league-sync` survives that deletion because it is not a migration: it validates a *provider's* response on the way in, and it may *discard* it — a sync is a cache of somebody else's state, re-fetchable in one click, so a bad shape costs a button press while a half-repaired one costs a board that believes the wrong people are rostered. Opening the tab fetches its board once, since that is a second full rank of the universe.

My Team (`views/team.cljs`) is where the season half opens: the synced roster full width. The roster is the `:my-roster` sub, which is the manager's own card off the League tab's `:league-rosters` rather than a second reading of the sync, so My Team, the Waivers panel and the League tab cannot disagree about whom he holds. Its rows are the `/api/waivers` reply's `:my-roster-players`, and the reply's `:drop-candidate` marks the seat a claim would cost. The server used to split the manager's roster itself (`waiver/my-roster`), and the two splitters had already drifted apart on who counted as a starter. Every season tab fetches the matchup on first open (`db/matchup-view?`), because the season header's week is only ever the matchup reply's; the tabs that read the waiver reply are `db/waiver-views`. Its side cards — This week, Lineup check, Best claims — answer from boards already fetched and link to the tab that says more; the first two read `:my-matchup`, the manager's own game, not whichever game the Matchup tab has picked.

The season half's League tab is `:rosters` (`views/league.cljs`), not `:league` — a view's half is read off its key, and the draft half's League tab is a different screen (the auction room's picks and bankrolls). It reads every synced team in the browser through `db/team-roster`, the only function that splits a roster into starters, bench and IR/taxi, which goes through `db/held-ids` and seats starters with `db/starter-seats`: a team's own `:starter-slots` where it names them (ESPN, whose lineup is not positional against `:roster-positions`), `:roster-positions` by index only for Sleeper, and no label otherwise. Each card tags its team's bidding style off the sync's `:bid-history` profiles (`:league-bid-profiles`, which turns `:style` back into a keyword, since it crosses JSON as a string), with `bid-history/style-line` as the tag's title and FAAB as a bare amount. A league whose host has no history carries no tag, while a manager who has never bid in one that does reads "No bids yet".

The Matchup view (`views/matchup.cljs`) is the third board and the one that is *not* a table of toggleable columns — it is a fixed two-sided layout, one row per lineup seat with the slot label down the middle, which is `views/compare`'s grid one scale up and for its reason: the comparison is the whole point of the screen. So it has no column catalog and nothing of its own in `persist-keys`. Projected is muted and actual is bold, because a projection is a claim and a result outranks it; **a dash is not a zero** — `:actual` is nil until kickoff, and rendering that as `0.00` would turn a Sunday morning into nine bad performances, which is what `.mu-a.pending` exists to keep apart. The bench is drawn dimmed rather than hidden, since a best lineup is drawn *in place of* the set one — a player it moves in marked ▲, a starter it benches leading the bench marked ▼ — and "start him" is not advice if the reader cannot see what he did.

`:matchup-pick` names **a roster id, not a matchup id**. A roster with no opponent carries a nil matchup id, which collides exactly with "nothing picked" — keying on it made a byed manager's own week both the default selection and the one game he could not pick. Switching games costs no round trip, since the server valued every roster in one reply. `:set-active-league` drops `:matchup` and `:matchup-pick` (the board states who you are playing and what he scored; under another league's name those are false, not stale) and refetches only while a season tab is on screen, since each of them shows its week — Settings and the draft half pick it up from `:set-view`'s first-open fetch, and this is the one board whose fetch is live.

**`rf/reg-sub` takes no docstring.** A string in that position is read as an input spec and registers a handler that cannot be derefed, with no compile error — so every sub in `subs.cljs` documents itself in a `;;` comment above the form.

The board is data-driven: `:columns` is an ordered vector of `{:key :visible?}` against `db/column-catalog`, so columns can be toggled/reordered without touching render code. A catalog change needs no storage bump — see above.

Which tier scale the board shows is not a setting: `:board-players` resolves `:tier` from `[:tiers (db/tier-scale pos-filter)]`, shadowing the flat alias the server ships, so a position filter switches scale with no refetch and everything downstream (row striping, the legend, the Tier column, sorting) keeps reading one key. Rows are tier-striped in every view for the same reason — before the overall scale existed, striping was switched off unless filtered, because a tier 2 RB beside a tier 2 WR meant nothing.

`(:config :scoring)` is either a preset keyword (`:standard`/`:half-ppr`/`:ppr`) or, once a manager customizes or imports, a full `{stat-key weight}` map — mode is derived (`:scoring-mode` sub), never stored separately. A *connected* league's settings are not editable at all: scoring, roster, team count and — once an import has supplied one — the auction budget are whatever its import said. `db/league-owned-keys` is the one statement of that set; Settings and the Start Draft modal draw those keys read-only off it, and hand edits go through `:edit-config`, which drops them (`:apply-config` stays the import's own path). An editable copy is what kept Re-sync from refreshing the rules, so Re-sync (`:refresh-league`) now re-imports alongside the roster sync, and an import that changes nothing applies nothing — no re-rank for a button pressed after every claim. What the import could not apply, whether it brought a budget, or why it failed is stored on the league entry as `:rules`, persisted, so the warning outlives a reload; a failure is assoc'd beside the last good import rather than replacing it, since those settings are still the ones in force. A failed import says the board is still on the previous settings rather than passing them off as this league's, and there is deliberately no hand-edit escape hatch. Coercing that field to a weight map is `scoring/resolve-config`, used by both `routes/resolve-scoring` and the `:scoring-format` sub: the browser derives which vendor format its league reads from the same field the server does, and hand-written copies of that `cond` had already drifted on the string spellings. The preset table and `stat-keys` live in shared `src/cljc/draft_day/scoring.cljc` so the editor can seed a custom map synchronously; there is deliberately no endpoint serving them, because seeding from an async fetch is what used to write a nil scoring config. `stat-keys` is every rule a host exposes (88 of them) while a preset prices only the twenty-nine a named format is about — `scoring/stated-only` is the rest, at 0.0, so Standard/Half/PPR stay byte-identical and an import still has a key to land every rule on. `scoring/unprojected-stats` is then the keys *neither* projection horizon carries, which is what the editor greys out and what `scores-anything?` refuses to count. One set and not two, because the season-line fill below makes a weekly-only key reach the draft board like any other — which is also why `:ff`, `:def_td` and `:safe` are no longer in it. Field goals are scored *by distance*, because every host scores them that way and the grids differ — Sleeper splits everything under forty into three buckets and stops at 50+, ESPN uses one band under forty and splits 50-59 from 60+ — so `scoring/fg-buckets` names the made-kick keys and the flat `:fgm` yields to any of them that carries a weight (`sleeper/scored-stats` publishes both, and weighting both pays for one kick twice). The two Sleeper projection lines disagree about which buckets they publish — the weekly carries every make under fifty, the season the two over forty — so ingestion carries both sets and each line scores what it has; that is what makes the board agree with Sleeper's own totals on both (Aubrey 118 against 116 for a season, Bass 6.96 against 6.85 for a week). Everything *else* the season line is silent about is filled from the week-one line instead (`sleeper/complete-season-line`), scaled by that player's own implied games — `pts_ppr` season over `pts_ppr` week, clamped to seventeen because the two horizons disagree hard about a marginal player and an unclamped ratio reached thirty. Without it, widening the vocabulary is not a neutral gain but a tilt: the buckets the season line does publish are receiving ones, so receivers and tight ends gain and quarterbacks and defenses do not, and VORP compares those directly. Filled, a starting quarterback gains about 8 points a season and a starting defense about 72 — three quarters of what it was reading — while receivers barely move. Made field goals are exempt and that carve-out is load-bearing: the two horizons *disagree* about that grid rather than covering different parts of it, and filling one from the other read Aubrey as thirty-one makes against the seventeen his season line states, scoring him 160 against Sleeper's 116. A player Sleeper projects no week for keeps the sparse line, which is a third of the universe and none of the top of it. `db/scoring-catalog` groups the stat keys for the custom editor in `views/settings.cljs` — ten groups now, each with `:stats` (what a named format is about, always drawn) and `:more` (everything else a host exposes, behind a `<details>` that opens when the league puts a weight inside it). Eighty-eight fields in one grid is a worse editor than twenty-nine was, and every rule in `:more` is zero in a league that has not imported one; the tier families are entirely `:more`, so a manager hand-rolling a PPR league never sees them. Presentational metadata only, not the same shape as `column-catalog` (flat, no grouping). `settings/import-warning` reports **two** states and not one, because collapsing them is what made the old warning confusing: a rule with no key scores nothing anywhere ("not modelled" — the position reception premiums, which price one stat by who earned it and so need two weights), while a rule the model holds that no projection carries still scores the weeks that have happened ("no projection" — it moves the in-season boards and cannot move the draft board). The sidebar badge counts only the first. League import (`:import-league` in `events.cljs`) POSTs to `/api/league/import` rather than calling a provider's API directly from the browser — the shared `fetch`-based `:http` effect (`fx.cljs`) checks `resp.ok` and routes any non-2xx to `on-failure` with the body's `:error`.
